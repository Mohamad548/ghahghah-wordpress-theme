# هدر قهقهه — راهنمای پیاده‌سازی در Cursor

نسخه ۱ — ۱۴ سپتامبر ۲۰۲۶

این سند همراه تصویر هدر به Cursor داده شود. تصویر مرجع ظاهر است؛ این سند مرجع رفتار، تنظیمات و معیار پذیرش است. این خروجی مشخصات طراحی است و به‌معنای ساخته‌شدن تنظیمات جدید در وردپرس نیست.

## دستور اجرا برای Cursor

هدر قالب موجود `ghahghah-theme` را مطابق تصویر پیوست و این سند پیاده‌سازی کن. ابتدا کد فعلی، دستورالعمل‌های مخزن و تغییرات ذخیره‌نشده کاربر را بخوان. کاربر هم‌اکنون روی UI کار می‌کند؛ تغییرات او را حفظ کن. بدون نیاز به جابه‌جایی شاخه، بازسازی استارتر یا تغییر افزونه Core، کار را در وضعیت فعلی پروژه ادامه بده. اگر این سند با بخشی از تصویر اختلاف دارد، رفتار و مقادیر این سند مرجع هستند.

محدوده این کار هدر، ناوبری دسکتاپ و موبایل و تنظیمات مرتبط با هدر در قالب است. Hero و بقیه صفحات وظیفه این مرحله نیستند. از منو و custom logo استاندارد وردپرس استفاده کن؛ منوی موازی یا سیستم تنظیمات جداگانه در Core نساز.

مسیر پروژه روی کامپیوتر کاربر: `E:\word pares\ghahghah-wordpress theme`.

## ۱. ساختار بصری

هدر سفید، راست‌به‌چپ و هماهنگ با مرجع قبلی قهقهه است. روی دسکتاپ لوگو راست، ناوبری میانه و دکمه «درخواست خرید عمده» چپ قرار می‌گیرند. ترتیب منطقی فهرست نمونه از راست به چپ: «صفحه اصلی»، «محصولات»، «کارخانه»، «مقالات»، «تماس با ما».

این عنوان‌ها نمونه چیدمان‌اند. خروجی واقعی باید از فهرست تعیین‌شده مدیر خوانده شود. عنوان، ترتیب، مقصد و زیرمنوها را داخل PHP یا JavaScript ثابت ننویس. فعال‌شدن قالب نباید برگه یا فهرست آزمایشی بسازد.

ارتفاع‌ها حداقل‌اند؛ بزرگ‌شدن متن یا لوگوی مجاز نباید باعث برش محتوا شود. نسبت لوگو حفظ شود و تصویر کشیده یا بازطراحی نشود. ارتفاع مجاز لوگو بر عرض انتخاب‌شده اولویت دارد. برای آیتم‌های منو عرض ثابت نگذار. اگر فهرست واقعی در یک ردیف جا نشد، حالت جمع‌شده را زودتر فعال کن؛ لینک‌ها نباید روی هم بیفتند یا پنهان شوند.

رنگ‌ها: قرمز برند `#D71920`، متن `#222222`، پس‌زمینه `#FFFFFF` و جداکننده ملایم. از توکن‌های موجود قالب و فونت فارسی محلی پروژه استفاده کن. متن صفحه فعال قرمز و دارای خط کوتاه زیر آن باشد. تمرکز کیبورد باید نشانه واضح و مستقل داشته باشد. برای اندازه‌های معمول متن روی دکمه، ترکیب سفید و قرمز برند حفظ شود.

شماره‌های توضیحی، عنوان شیت، اندازه‌ها و کارت «قابل ویرایش در وردپرس» جزء سایت نیستند. آن‌ها را وارد HTML هدر نکن. گوشه‌های گرد قاب‌های نمایش در شیت نیز جزء قاب ارائه‌اند؛ هدر واقعی یک نوار سفید تمام‌عرض با لبه‌های صاف و محتوای میانی محدود است. تصویر کامل شیت یا هدر را به‌عنوان یک تصویر قابل کلیک در سایت قرار نده؛ اجزای آن باید HTML واقعی باشند.

## ۲. ناوبری دسکتاپ و موبایل

### دسکتاپ

- منوی وردپرس با location موجود `primary` رندر شود. لینک فعال با کلاس‌های استاندارد وردپرس و `aria-current` مشخص شود.
- والد زیرمنو لینک قابل استفاده داشته باشد و کنار آن یک دکمه مستقل برای باز و بسته‌کردن فرزندان قرار بگیرد. کلیک روی لینک والد نباید به‌اجبار فقط زیرمنو را باز کند.
- دکمه زیرمنو از `aria-expanded` و `aria-controls` درست استفاده کند. حداقل یک سطح زیرمنو مطابق تصویر پشتیبانی شود؛ ساختار عمیق‌تر موجود کاربر را بدون گزارش حذف نکن.
- زیرمنو با کلیک یا Enter/Space باز شود؛ Escape آن را ببندد و تمرکز را به دکمه مربوط برگرداند. خروج تمرکز و کلیک بیرون نیز منو را به حالت مناسب ببرد. بازشدن صرفاً وابسته به hover نباشد.
- زیرمنو به لبه راست محرک خود متصل باشد و در لبه صفحه بریده نشود.
- آیتم‌های «همه محصولات»، «طعم پیتزا» و «طعم لیمویی» داخل تصویر فقط نمونه زیرمنوی قابل تنظیم هستند؛ برای تولید این ظاهر، محصول یا taxonomy جدید نساز.

### موبایل

- در حالت بسته، لوگو راست و دکمه همبرگری چپ باشد. دکمه خرید عمده در کشوی باز نمایش داده شود و فضای هدر بسته را اشغال نکند.
- کشو از راست باز شود؛ بقیه صفحه یک پوشش نیمه‌شفاف داشته باشد. ضربدر بستن در بالای چپ کشو و لوگو در بالای راست آن قرار بگیرد.
- محتوای کشو از همان منوی `primary` خوانده شود. نیاز به تنظیم دوباره منوی موبایل نباشد.
- فرزندان منو با دکمه مستقل به‌شکل آکاردئون باز شوند. لینک والد همچنان قابل رفتن به مقصد باشد.
- کشو در ارتفاع کم قابلیت اسکرول داشته باشد؛ دکمه خرید عمده نباید روی آخرین آیتم‌ها بیفتد. با تغییر جهت صفحه یا بسته‌شدن کشو، قفل اسکرول باقی نماند.
- هنگام بازبودن حالت modal، تمرکز داخل آن بماند و پس‌زمینه برای تعامل و ابزار کمکی غیرفعال باشد. با Escape، دکمه بستن و کلیک روی پوشش بیرونی بسته شود. پس از بستن، تمرکز به همبرگر برگردد.
- اگر با تغییر اندازه صفحه به حالت دسکتاپ برگشتیم، کشو، overlay و قفل اسکرول پاک شوند. موقعیت قبلی اسکرول صفحه حفظ شود.
- از ناوبری معنایی `nav / ul / li / a / button` استفاده کن؛ برای ناوبری معمول سایت بی‌دلیل `role="menu"` نگذار. شناسه‌های DOM در نسخه دسکتاپ و موبایل یکتا باشند.
- بدون JavaScript نیز مسیر دسترسی به لینک‌های اصلی باقی بماند؛ یک منوی کاملاً مخفی و غیرقابل استفاده تحویل نده.
- انیمیشن کوتاه و ملایم باشد و `prefers-reduced-motion` رعایت شود.

هدر به جست‌وجو، زبان، ورود حساب کاربری، سبد خرید یا نوار تبلیغاتی جدید نیاز ندارد.

## ۳. موارد قابل ویرایش در پنل مدیر

| مورد | محل ویرایش | جزئیات |
| --- | --- | --- |
| فایل لوگو | نمایش ← سفارشی‌سازی ← هویت سایت | استفاده از `custom_logo` استاندارد؛ انتخاب از رسانه وردپرس |
| عنوان، لینک، ترتیب و زیرمنو | نمایش ← فهرست‌ها؛ جایگاه «منوی اصلی» | استفاده از `primary`؛ افزودن، حذف و جابه‌جایی از رابط استاندارد |
| اندازه لوگو | نمایش ← سفارشی‌سازی ← هدر قهقهه | کنترل عددی جدا برای دسکتاپ و موبایل |

لوگو و مدیریت فهرست‌ها باید از امکانات استاندارد موجود استفاده کنند. بخش «هدر قهقهه» و تنظیمات جدید آن بخشی از پیاده‌سازی مورد درخواست‌اند؛ وجود آن‌ها در نسخه نصب‌شده فعلی فرض نشود. در نسخه‌هایی از ترجمه وردپرس ممکن است «نمایش» با عنوان «پوسته/Appearance» یا «سفارشی‌سازی» با عنوان «سفارشی‌کردن» دیده شود.

نام بخش Customizer: `ghahghah_header` با عنوان «هدر قهقهه». داده‌های مربوط به ظاهر هدر از نوع `theme_mod` و دارای مجوز `edit_theme_options` باشند. برای تغییر ظاهر، به نقش Editor مجوز مدیریتی تازه اضافه نکن.

| کلید پیشنهادی | نوع | پیش‌فرض | اعتبارسنجی |
| --- | --- | --- | --- |
| `ghahghah_header_logo_width_desktop` | integer | 144 | بین 80 و 200 |
| `ghahghah_header_logo_width_mobile` | integer | 112 | بین 72 و 140 |
| `ghahghah_header_cta_enabled` | boolean | true | مقدار بولی معتبر |
| `ghahghah_header_cta_label` | string | درخواست خرید عمده | متن ساده؛ حداکثر 40 نویسه با احتساب درست فارسی |
| `ghahghah_header_cta_page_id` | integer | 0 | شناسه برگه قابل مشاهده عمومی |
| `ghahghah_header_sticky` | boolean | true | مقدار بولی معتبر |

اگر تنظیمات هم‌معنا از قبل وجود دارند، به‌جای افزودن کلید موازی از آن‌ها استفاده و نام واقعی را در گزارش ثبت کن. رنگ، فونت، فاصله‌ها و اندازه آیکون‌ها از توکن‌های طراحی قالب پیروی کنند؛ این کار به سازنده عمومی هدر تبدیل نشود.

تنظیمات و مقادیر پیش‌فرض تعریف‌شده در Customizer و محل رندر باید یکسان باشند. برای کنترل‌های این مرحله پیش‌نمایش با refresh کافی است؛ ابزار جدید برای live preview اضافه نکن.

## ۴. رفتار در وضعیت‌های ناقص و امنیت

- اگر لوگو انتخاب نشده، نام سایت به‌صورت لینک خانه نمایش داده شود. `home_url('/')` مقصد لوگو است. از لوگوی اختصاصی کاربر استفاده کن؛ تصویر را از شیت طراحی برش نزن یا با متن شبیه‌سازی نکن.
- اگر منویی به `primary` اختصاص داده نشده، تمام برگه‌ها را خودکار فهرست نکن. لوگو/لینک خانه قابل استفاده بماند و راهنمای تنظیم فقط برای مدیر در محیط مناسب نمایش داده شود.
- CTA فقط وقتی رندر شود که فعال است، متن غیرخالی دارد و برگه مقصد واقعاً عمومی است. تا پیش از ساخت صفحه خرید عمده، لینک `#` یا آدرس فرضی نساز.
- حذف، خصوصی یا پیش‌نویس‌شدن برگه مقصد باید CTA را از خروجی عمومی حذف کند. وضعیت مقصد هنگام رندر هم کنترل شود؛ اعتبارسنجی زمان ذخیره به‌تنهایی کافی نیست.
- فرم یا پردازش خرید عمده در این مرحله ساخته نشود. هدر فقط به برگه پیکربندی‌شده لینک می‌دهد.
- هدر، منو و تنظیمات آن بدون فعال‌بودن `ghahghah-core` نیز کار کنند. برای لینک‌های محصولات از مقصد ذخیره‌شده در منوی مدیر استفاده شود و وابستگی مستقیم به کلاس‌های Core ایجاد نشود.
- ورودی‌ها در Customizer اعتبارسنجی و پاک‌سازی شوند و خروجی متناسب با متن، attribute و URL escape شود. از اجرای کد دلخواه در تنظیمات یا چاپ CSS/HTML خام کاربر خودداری کن.
- لوگو عرض و ارتفاع واقعی HTML داشته باشد، lazy-load نشود و نسبت تصویرش حفظ شود. برای هدر از فونت CDN یا کتابخانه UI جدید استفاده نکن.
- هدر چسبان فضای اصلی خود را در جریان صفحه نگه دارد؛ هنگام اسکرول اندازه آن ناگهان عوض نشود. در حالت ورود مدیر، نوار مدیریت وردپرس را در دسکتاپ و موبایل نپوشاند و فاصله خالی اشتباه ایجاد نکند.
- لینک پرش به محتوای اصلی و ساختار دسترس‌پذیری موجود قالب حفظ شود.

## ۵. محدوده فایل‌ها و حفظ کار جاری

از `header.php`، فایل‌های setup/assets/template-tags موجود و ساختار فعلی قالب استفاده کن. در صورت نیاز یک فایل کوچک مثل `inc/header-settings.php` و فایل اختصاصی CSS/JS هدر اضافه کن. نام‌گذاری نهایی را با پروژه تطبیق بده.

تابع `ghahghah_the_nav()` ممکن است در فوتر نیز استفاده شود. اگر آن را تغییر می‌دهی، رفتار فوتر را ناخواسته تغییر نده؛ برای هدر آرگومان یا تابع اختصاصی مناسب تعریف کن. `wp_head()`، `wp_body_open()`، کلاس‌های body و سازوکار enqueue استاندارد حفظ شوند.

به کد افزونه، قرارداد داده محصول، فرم‌ها، SMS، فایل‌های خام تصویر و محتوای دیگر صفحات دست نزن. هیچ انتشار روی GitHub یا سایت زنده از این سند لازم نیست. تغییرات را برای بررسی محلی آماده کن و در پایان گزارش بده.

## ۶. معیار پذیرش

1. ظاهر در عرض‌های 320، 390، 768، 1024 و 1440 بررسی شود؛ اسکرول افقی یا هم‌پوشانی وجود نداشته باشد.
2. متن و ترتیب منوی مدیر و زیرمنوها، بعد از ذخیره، در هر دو حالت دسکتاپ و موبایل منعکس شوند.
3. تغییر لوگو، اندازه‌های آن، متن/مقصد/نمایش CTA و چسبان‌بودن هدر اعمال و بعد از بارگذاری مجدد حفظ شوند.
4. حالت بدون لوگو، بدون منو، بدون مقصد CTA و بدون Core سالم بماند.
5. ناوبری کیبورد، Escape، برگشت focus، بستن overlay، قفل اسکرول و تغییر breakpoint عملاً بررسی شوند. کنسول مرورگر خطا نداشته باشد.
6. دست‌کم یک بار با کاربر واردشده و یک بار خارج‌شده بررسی شود. رفتار بدون JavaScript نیز آزمایش شود.
7. نبود محصول یا صفحه فرم جدید، مانع نمایش سالم هدر نشود. اطلاعات تجاری یا برگه ساختگی برای پرکردن UI ایجاد نشود.
8. lint و بررسی‌های مرتبط موجود پروژه اجرا شوند. برای کنترل‌های امنیتی و رفتار حفظ/پاک‌سازی تنظیمات، فقط تست‌های معنادار اضافه شود؛ برای مقادیر ثابت CSS تست تکراری ننویس.
9. دو اسکرین‌شات از اجرای واقعی تحویل بده: هدر دسکتاپ و کشوی باز موبایل. این‌ها باید از سایت اجراشده باشند، نه تصویر مرجع.
10. گزارش نهایی شامل فایل‌های تغییرکرده، مسیر دقیق تنظیمات، بررسی‌های انجام‌شده و هر مورد اجرا‌نشده باشد. بدون اجرای واقعی، ادعای تست موفق نکن.
